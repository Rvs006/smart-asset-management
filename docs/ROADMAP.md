## Build Philosophy
Reuse the Smart Commissioning Tool's stack and GUI verbatim (React 19 + Vite + react-router + TanStack Query; FastAPI + SQLite local profile; import SCT's two CSS files). Build the magic-moment path first — a real import that surfaces cross-trade duplicates and invalid references — then widen. Every phase leaves a runnable app. Project metadata is schema-as-data + per-asset JSON, never a table per project. Validate on the server; the grid reflects it.

- [ ] **TASK-054** — Undo / redo. (#8)
  Files: `backend/app/db.py` (`audit_event.undone INTEGER DEFAULT 0` + migration), `backend/app/api/routes/assets.py`, `backend/app/api/routes/audit.py`, `frontend/src/api/queries.ts`, `frontend/src/features/assets/AssetManagementPage.tsx`
  Notes: Linear undo stack on `audit_event`, two new columns: `undone INTEGER NOT NULL DEFAULT 0` and `reversible INTEGER NOT NULL DEFAULT 0`. Only rows written by v0.1.4+ code with a complete snapshot get `reversible=1`; every pre-existing row stays `0` (a history cutoff), because today's payloads cannot be inverted — `patch_asset` stores `before.metadata` as a JSON string but `after.metadata` as an object, `create` omits `trade_id`, `delete` stores only the name and `bulk_delete` only a count. New snapshots are uniform: `{id, trade_id, instance_name, metadata: <object>}` in both `before` and `after` for `edit`, in `after` for `create`, in `before` for `delete`; `bulk_delete` emits one `delete` event per asset. Barriers: the stack walks the newest `undone=0` event of ANY action; if that event is not `reversible` (an `import`, `generate_names`, or any legacy row) undo stops there — `can_undo=false` with `reason: "last change was an import"` — rather than reaching past it to an older edit and overwriting what the later operation wrote. (`generate_names` starts writing an audit row per run so it acts as a barrier.) `POST /projects/{pid}/undo`: apply the inverse (PATCH back to `before` / DELETE / re-INSERT with the same id), mark `undone=1`, re-validate. `POST /redo`: oldest `undone=1` → re-apply `after`, mark `undone=0`. Any new user mutation deletes rows with `undone=1` (redo stack cleared). Inverse writes do not add audit rows. Scope: cell edits, add, delete, duplicate. Import and Generate names are not undoable in v0.1.4 (say so in the button tooltip). `GET /undo-state` → `{can_undo, can_redo, last_action, reason}` for button state.
  Verify: edit a cell → Undo restores the old value → Redo re-applies; delete a row → Undo brings it back with the same id; edit, then import → Undo is disabled with the import reason and the earlier edit is NOT undoable until the history is newer than the import; on a DB upgraded from v0.1.3, Undo is disabled until the first new edit.

  Files: `backend/app/validation.py`, `frontend/src/features/configuration/ConfigurationPage.tsx`
